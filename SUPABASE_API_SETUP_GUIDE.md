# Supabase Edge Functions API Setup Guide 🔧

## Problem: Authentication Errors in SquidCloud API

You're experiencing authentication errors with the SquidCloud API edge function. This guide explains how to properly set up Supabase Edge Functions without interfering with your custom API.

## Current Issues 🐛

1. **SquidCloud API (`cloudbliss-api`) returns authentication errors**
2. **Confusion about which authentication method to use**
3. **Need to separate Supabase auth from custom API key auth**

## Understanding the Two API Systems 🔍

### 1. **Supabase Built-in APIs** (RLS-based)
- Uses Supabase's `anon` key or service role key
- Authentication via JWT tokens (`Authorization: Bearer <jwt>`)
- Row Level Security (RLS) policies enforce permissions
- Used for: Direct database queries, Supabase Storage

### 2. **SquidCloud Custom API** (API Key-based)
- Uses custom API keys generated by your app
- Authentication via `X-SquidCloud-Key` header
- Custom validation logic in Edge Functions
- Used for: External integrations, third-party access

## Proper Setup for Each System ⚙️

### Option 1: Using Supabase Direct Access (Recommended for App)

**When to use:** Your web app making direct calls to Supabase

**Authentication:**
```typescript
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(
  'https://aouqcwbdoyrccjcrhzzi.supabase.co',
  'YOUR_ANON_KEY' // Public anon key
)

// Users automatically authenticated via Supabase Auth
// RLS policies handle permissions
const { data } = await supabase
  .from('files')
  .select('*')
```

**No edge function needed!** Direct access is faster and simpler.

### Option 2: Using SquidCloud API (For External Access)

**When to use:** Third-party apps, CLI tools, external integrations

**Authentication:**
```bash
curl -X GET \
  -H "X-SquidCloud-Key: cb_your_api_key_here" \
  https://aouqcwbdoyrccjcrhzzi.supabase.co/functions/v1/cloudbliss-api/files
```

**Edge Function Flow:**
1. Request arrives with `X-SquidCloud-Key` header
2. Function hashes the key with SHA-256
3. Looks up key in `api_keys` table
4. Validates key is active and has correct scopes
5. Performs operation on behalf of key owner

## Fixing Authentication Errors 🔨

### Issue 1: Missing or Invalid API Key

**Error:**
```json
{
  "error": "SquidCloud API key required. Include it in X-SquidCloud-Key header.",
  "success": false
}
```

**Fix:**
1. Generate an API key from your app's Developer API section
2. Include it in the request:
   ```bash
   -H "X-SquidCloud-Key: cb_xxxxxxxxxxxxx"
   ```

### Issue 2: Using Wrong Authentication Method

**Wrong:**
```bash
# DON'T use Supabase anon key with SquidCloud API
-H "Authorization: Bearer eyJhbGciOiJI..."
```

**Right:**
```bash
# DO use SquidCloud API key
-H "X-SquidCloud-Key: cb_xxxxxxxxxxxxx"
```

### Issue 3: API Key Not Found in Database

**Error:**
```json
{
  "error": "Invalid SquidCloud API key",
  "success": false
}
```

**Fix:**
1. Check if API key exists in `api_keys` table
2. Verify `is_active = true`
3. Regenerate key if needed

**SQL to check:**
```sql
SELECT * FROM api_keys 
WHERE user_id = 'your-user-id' 
AND is_active = true;
```

## Separating Supabase Auth from Custom API 🔐

### For Your Web App (Use Supabase Direct):

**✅ DO:**
```typescript
// src/integrations/supabase/client.ts
export const supabase = createClient(
  process.env.VITE_SUPABASE_URL!,
  process.env.VITE_SUPABASE_ANON_KEY!
)

// No need for Edge Functions!
// RLS policies protect data automatically
const { data } = await supabase
  .from('files')
  .select('*')
  // RLS automatically filters to current user's files
```

**❌ DON'T:**
```typescript
// Don't call Edge Functions from your own app
fetch('/functions/v1/cloudbliss-api/files', {
  headers: { 'X-SquidCloud-Key': 'cb_xxx' }
})
```

### For External Tools (Use SquidCloud API):

**✅ DO:**
```bash
# External CLI tool
curl -X GET \
  -H "X-SquidCloud-Key: cb_xxxxxxxxxxxxx" \
  https://yourproject.supabase.co/functions/v1/cloudbliss-api/files
```

## Configuring Edge Function CORS 🌐

If you're calling the Edge Function from a web app, update CORS:

**`supabase/functions/cloudbliss-api/index.ts`:**
```typescript
const corsHeaders = {
  'Access-Control-Allow-Origin': '*', // Or your domain
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type, x-squidcloud-key',
  'Access-Control-Allow-Methods': 'POST, GET, OPTIONS, PUT, DELETE',
}

// Handle preflight
if (req.method === 'OPTIONS') {
  return new Response('ok', { headers: corsHeaders })
}
```

## Environment Variables Setup 📋

### For Edge Functions:

Edge Functions automatically have access to:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` (full access, bypasses RLS)
- `SUPABASE_ANON_KEY` (public key, respects RLS)

**No additional setup needed!**

### For Your Web App:

**`.env`:**
```bash
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
```

## Common Errors and Solutions 🚨

### Error: "Invalid SquidCloud API key"

**Causes:**
1. API key doesn't exist in database
2. API key is inactive (`is_active = false`)
3. Wrong API key format
4. Key hash doesn't match

**Solution:**
```typescript
// Generate new API key from app
// Or check database:
SELECT * FROM api_keys WHERE is_active = true;
```

### Error: "CORS error when calling Edge Function"

**Cause:** Missing CORS headers

**Solution:**
Add to Edge Function:
```typescript
const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': '..., x-squidcloud-key',
}
```

### Error: "Authentication required" (Supabase RLS)

**Cause:** User not signed in, RLS policy blocking

**Solution:**
```typescript
// Make sure user is authenticated
const { data: { user } } = await supabase.auth.getUser()
console.log(user) // Should not be null
```

## Best Practices ✨

### 1. **Use Direct Supabase Access for Your App**
- Faster (no Edge Function overhead)
- Simpler (no API key management)
- More secure (RLS policies)

### 2. **Use Edge Functions Only for External Access**
- Third-party integrations
- CLI tools
- Public APIs

### 3. **Never Mix Authentication Methods**
```typescript
// ❌ DON'T
fetch('/functions/v1/cloudbliss-api/files', {
  headers: {
    'Authorization': 'Bearer <jwt>',        // Supabase auth
    'X-SquidCloud-Key': 'cb_xxx'           // Custom auth
  }
})

// ✅ DO (pick one)
// Option A: Direct Supabase
const { data } = await supabase.from('files').select('*')

// Option B: External API
fetch('/functions/v1/cloudbliss-api/files', {
  headers: { 'X-SquidCloud-Key': 'cb_xxx' }
})
```

### 4. **Secure Your API Keys**
- Store in environment variables
- Rotate regularly
- Monitor usage via `last_used_at`
- Revoke compromised keys immediately
